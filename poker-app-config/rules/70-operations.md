# Operations

Source: `launch-kit/06-operations/` (OPS-01…25). `docs/launch-runbook.md` is
canonical for launch order and incident response — this file is the day-to-day.

## The scripts are the interface

| Script | Does |
|---|---|
| `scripts/preflight.sh` | Says what is still missing before launch. Run it before claiming anything is ready |
| `scripts/configure-launch.sh` | Fills the three placeholders everywhere, rewrites canonical/OG URLs, sitemap, robots.txt, 404 paths, writes CNAME |
| `scripts/enable-adsense.sh` | Sets the publisher ID. **Passing `""` is the advertising kill switch** |

Do not hand-edit what these scripts generate. If a script's output is wrong, fix
the script.

## Recovery

- **Rollback:** `git revert HEAD && git push` — live in ~45 seconds, measured.
- **Kill ads without a rollback:** `sh scripts/enable-adsense.sh ""`.
- **Full takedown:** GitHub → Settings → Pages → Source: None. Gone in under a
  minute.
- **Recovery of the site is `git clone`.** There is no database, so there is
  nothing else to restore. This is the whole disaster-recovery plan and it is
  adequate *because of* the invariant in `00-core.md`.

## Cost and scale

No server means no runaway bill and no scaling story. If that ever changes,
spend caps and a backup policy become real work — `launch-kit/06-operations/`
has the rules.

## Tests

`sh test/run.sh`. `test/build/` is generated by `test/build.py` from
`index.html` — never edited, never committed.
